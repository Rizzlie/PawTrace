# Compose one CaseStore from focused NgRx Events features

The user chose NgRx SignalStore with Events after comparing plain signals services with a single store composed from focused features. Use one plain state containing the committed document, isolated editor draft, transfer candidate and persistence bookkeeping; compose projections, persisted map-view commands, animal editing, file transfer and persistence as separate `signalStoreFeature` modules. This replaces ADR 0003's separate state-owning services while retaining its responsibility split and Angular/Leaflet adapter boundary.

Reducers own all state changes, including atomic profile Save (document, editor closure and revision). Async handlers perform parsing/storage, and narrow result-returning commands support forms and cancellable route guards. Form effects/injectors and pending Promise/AbortController resources stay outside serializable state, with explicit cleanup; they do not hold a second draft. Provide the store and dispatcher together in the workspace route so unrelated instances cannot observe each other's events. Preserve lazy domain validation, request/session correlation, revision-aware autosave and the existing durable replacement barrier. map-engine receives plain bindings and emits technical intents; it has no store injection or case business rules.
