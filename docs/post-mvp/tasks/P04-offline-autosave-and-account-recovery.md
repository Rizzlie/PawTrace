## Assumptions and sources

- Read [the specification](../spec.md): Authentication and session; Autosave, offline work, and conflicts, plus [execution rules](README.md).
- The user accepted IndexedDB during connectivity loss, synchronization on return, separate pending state per case, seven-day API inactivity, and clearing local copies on explicit logout after warning/export/cancellation.
- The existing [frontend architecture](../../architecture/frontend.md), [document-only persistence ADR](../../adr/0002-one-state-with-document-only-persistence.md), and [store composition ADR](../../adr/0004-compose-case-signal-store-with-events.md) define the committed-document writer, isolated drafts and generation-aware events. Extend those seams rather than creating another state owner.
- P02 provides complete online case persistence, versions and safe stale-write rejection. Photo transport is not required to verify this data-save slice; local JSON export already exists as a recovery primitive.

## Scope

Deliver durable local saving and reconnection for an already running application. Key snapshots, pending revisions and acknowledged server versions by authenticated owner and case. Preserve the newest committed local state on connection loss, case switching, page interruption and delayed completion. Coalesce writes without acknowledging a revision newer than the request actually captured.

Show separate saving/server-saved/local-only/failure states. Retry on reconnection or an explicit action without spinning. Expired sessions pause synchronization, preserve queued data, and require the same identity before resuming. Another account sees only its own data. Prevent a second tab from silently overwriting another tab's unsynchronized local branch.

Integrate conscious logout: warn, offer export/cancel, revoke the session and clear local copies/queues across tabs after confirmation. Wait for actual revocation before reporting success; retain recovery options on a failed request. Abort or fence old writes and callbacks so they cannot recreate cleared records. If local cleanup fails after revocation, report that state accurately and keep application access closed. Route detected version/deletion conflicts to a recoverable paused state; P05 supplies the full chooser/recovery UI.

## Acceptance criteria

- [x] Offline committed edits are saved in real IndexedDB and survive a browser interruption. Drafts/filters are excluded, and offline startup of the application is not promised.
- [x] Reconnection saves against the remembered server version. A successful local write never displays server-saved; a failed server write leaves pending data recoverable.
- [x] Switching cases retains each queue. Switching accounts never renders, exports or submits another owner's data, including after expiry/re-authentication.
- [x] Delayed saves from an old case, account or session generation cannot acknowledge new work, replace its snapshot or repopulate cleared logout storage.
- [x] Acknowledgement loss/retry reconciles the committed mutation safely rather than overwriting a newer server version. Coalescing preserves the newest local revision.
- [x] IndexedDB quota/transaction failure preserves latest in-memory data, shows a persistent warning, and leaves JSON export available. Repeated connection failures do not create an unbounded retry loop.
- [x] Two tabs editing a pending case do not silently destroy each other's local data. Divergent server/local work pauses with recovery available until P05 resolution is integrated.
- [x] Expiry preserves queued changes and asks for login; explicit confirmed logout revokes the server session and removes case copies across tabs. Cancelled logout changes neither queue nor session.
- [x] Online-only create/delete/import and photo uploads have explicit offline states; existing data/geometry edits remain available.

## Verification steps

1. Run focused existing snapshot/store tests and relevant Nx API/workspace/browser checks. Exercise an actual backend plus persistent browser profile and IndexedDB.
2. Load two cases, disconnect, edit both and switch between them. Reconnect and compare committed data on a second browser; close/reopen the profile to inspect durable pending state when the app can load again.
3. Force out-of-order responses, lost acknowledgements and a change while one save is in flight. Verify displayed revision/status and server content, not private callback call counts.
4. Abort an IndexedDB transaction and simulate quota failure, network timeout and server rejection. Export local JSON and prove it contains the latest committed data.
5. Advance server time beyond seven inactive days, reauthenticate as the same account and then a different account, and inspect visible data plus outgoing requests. Exercise logout cancellation, successful cleanup, failed revocation and an old in-flight callback after logout in another tab.
6. Edit the same case from two tabs while offline. Demonstrate both branches remain recoverable and neither is silently overwritten by local storage coordination.

## Discussion topics and decision record

- Settled: local durability before confirmed server acknowledgement, owner/case separation, expiry preserves work, explicit logout clears copies, no full offline startup.
- Record: IndexedDB schema/upgrade, tab coordination, retry/idempotency reconciliation, writer generation fences and failure-state transitions. Existing anonymous data must not be silently attributed to whichever account signs in first; the user will import JSON.
- Define the logout boundary across tabs and cleanup failure behavior. Do not reinterpret the chosen API-activity session timeout as foreground-only activity.

Implementation decisions (2026-11-02):

- Keep the route-scoped `CaseStore` as the only active document/draft owner. Extend its existing snapshot seam with an immediate local checkpoint, separate local acknowledgement/error fields, and bounded synchronization. Pending durable records are storage, not another application store. A failed old case must not block a different case's queued write.
- Native IndexedDB database `pawtrace.owned-cases`, schema 1: `copies` stores one committed snapshot per owner/case/tab branch, remembered server version, local and acknowledged revisions, paused state and any exact outstanding mutation; `owners` stores monotonic logout epochs and cleanup fences. Use strict-durability transactions and acknowledge only `oncomplete`. No anonymous database is opened or migrated. Documents are validated before restoration; drafts, filters, selections and file-only export metadata are excluded.
- A tab keeps its branch identity in sessionStorage and holds a lifetime Web Lock. A duplicated live tab gets a new locked identity; an inactive branch can be adopted after a browser interruption. Per-owner/case synchronization locks serialize tabs; divergent pending documents are retained independently and pause synchronization. JSON recovery can download every local case/branch, including branches no longer open. P05 remains responsible for choosing versions or restoring a deleted case under a new identity.
- Checkpoint every committed revision immediately, including map moves; retain the existing two-second settle delay only for server map saves. Serialize/coalesce server writes, persist the exact idempotency key/body/base version before sending, replay an uncertain mutation first, then read its current server version before using a historical acknowledgement as a base for newer data. A later version or missing case pauses rather than overwrites/recreates it. HTTP save/read waits are bounded at 15 seconds; reconnect, explicit retry, startup and a later committed edit trigger finite attempts, with no repeating retry timer.
- Capture authenticated owner/session generation and verify it before/after asynchronous operations and within the local transaction. The existing store generation fences case changes. Initial route activation can precede `/me`: wait for its identity before reading owner-keyed data, and distinguish initial identity resolution from an account replacement. Send an expected-owner header on case/photo/logout requests; the real authentication guard rejects an old tab whose cookie now belongs to another account. Session expiry closes private access and retains durable work. Account changes also fence import/export results and the final download continuation. Preload routed editing code while online so the running app can reach editors offline; no cold offline startup/service worker is promised.
- Confirmed logout first awaits actual server revocation. Failure retains the session, copies, export and cancellation. After revocation, close access and broadcast the owner fence; record cleanup intent independently in localStorage and the IndexedDB owner fence before deleting copies. A failed deletion leaves access closed, including after a fresh login; retry finishes cleanup. Successful cleanup retains a higher epoch so delayed callbacks cannot recreate deleted records and notifies other tabs. These markers contain no session material. Logout JSON export includes current committed memory and other durable cases/branches; unconfirmed drafts and original photo bytes remain excluded.
- Catalogue fallback explicitly identifies a failed/stale remote list and offers retry while exposing cached cases offline. Create/delete/import and photo upload stay online-only; both online and offline rename are validated committed changes through the same store/checkpoint path. Online rename waits for server acknowledgement; failure retains local recovery. Leaving a case only requires local durability.

## Scope boundaries

P05 owns the user-facing conflict chooser and deleted-case restore-as-new. P06 owns full ZIP export; JSON-only recovery is sufficient here. No offline new cases/deletion/import/photo uploads, guaranteed tiles, background service worker synchronization or automatic merge is included. No migration of legacy anonymous snapshots into an account.
