# workspace

Browser feature integration, separate from the Leaflet adapter and server code.

F13 photo integration lives under `photos/`, shared by profile, history-entry and area-check editors. `withPhotoEditing` checks case/generation/editor identity before attaching an upload to the authoritative draft. `withPhotoProcessing` owns metadata reads and explicit processing retries; its results remain transient. Restoration, opening a card and metadata polling do not change the document, editor draft/version, revision or autosave. An explicit profile/history/check Save reads the latest resolved metadata, validates the complete candidate and commits it atomically. Cards derive their presentation from that transient state and have separate, explicitly sourced thumbnail/preview error signals. Missing metadata hides original-download actions; a failed preview preserves the thumbnail, original reference and available original download.

`PhotoTransfers` hides the two-request upload queue, progress and confirmation state. A malformed successful response is unconfirmed rather than a failed write: retry resolves a known original filename through GET metadata and never repeats the POST. An unknown outcome without a trustworthy filename offers no automatic resubmission. Each batch is bound to the route store's `DestroyRef`; gallery closure or store destruction cancels active/queued work and releases callbacks. Already published originals remain retained on the server. Galleries project editor fields/photos only when their editor identity matches the active target. Server-local derivative names become globally unique logical filenames in JSON, while content resolves through the original filename on the current server.

`CaseStore` is one NgRx SignalStore provided with a scoped Events dispatcher in the lazy workspace route. Components, child routes and guards use that same instance; sibling workspace scopes do not receive each other's events; NgRx intentionally exposes ancestor events to descendants, so a workspace store must not be nested under another workspace dispatcher. `case-store/case-state.ts` defines the plain document/editor/transfer/persistence shape and defaults. Computed projections are separate from event reducers and I/O handlers. Private form injectors, abort controllers and pending route promises are resources, not serializable state or independent stores.

The composition has focused features:

- `withCaseProjections`: readonly derived values, including dirty/save status and replacement summary.
- `withCaseView`: immutable persisted viewport/basemap changes; no Leaflet rendering or separate MapState.
- `withEditorResources` / `withEditorLifecycle`: one discriminated active editor session, shared atomic commit/closure/revision reducers and cancellable Save / Discard / Stay. `EditorForm<T>` owns the session-scoped Signal Forms binding; `EditorTransition` owns the pending decision and aborts delayed Save.
- `withAnimalEditing`: profile draft conversion, form projection and validated Save.
- `withPhotoProcessing`: case-owned photo resolution, correlated metadata results and processing retries; cards only render state and dispatch user intents.
- `withCaseFilters`: UI-only filter criteria in `CaseState.filter`, reset by case replacement and never stored, exported or counted as a revision; projects filter activity, highlighted matches and per-outcome counts for the selected place.
- `withPointEditing`: point draft/scene projections, geographic placement, validated Save, selection and confirmed reference-safe removal.
- `withCaseFiles`: file parsing/export, request-correlated candidates, editor-close coordination and explicit replacement intent.
- `withCasePersistence`: restoration, synchronous revision observation, retries, write acknowledgements and durable replacement through `SnapshotWriter`.

All state mutations use named Events and reducers; no `patchState` calls or state-copying effects exist in workspace features. Async commands that must return a result to routing/form callers remain methods; they dispatch serializable results into reducers. Parsing and persistence execute in `withEventHandlers`. Signal Forms writes go through the session-scoped custom setter and a typed draft event. Validation still loads lazily and verifies the session/version before committing the resulting document and closing the editor in the same reducer.

`SnapshotWriter` keeps one active transaction and the latest pending revision. Failed autosaves retain memory and stop draining until the next committed change or explicit retry. Replacement blocks mutations synchronously, drains an active write, drops obsolete queued snapshots, persists the candidate and only then activates the new generation. Candidate/import request identifiers remain monotonic across replacement. The revision observer schedules storage only for a new committed revision; draft/status changes and autosave errors cannot create a retry loop.

`AnimalProfile` edits all optional profile fields and separate escape circumstances through Signal Forms. A private `linkedSignal` projection routes writes into the editor-owned draft; a session-scoped form injector is released on Save, Cancel or view destruction. Session identifiers and case generations reject stale field writes; cancellation also blocks a delayed Save. The public form tree exposes only the active draft. `profile-draft.ts` initializes stable native-control values and converts them explicitly into domain values on Save, preserving unknown/negative distinctions, time precision and imported photo metadata. Save validates the complete resulting document and publishes one revision. Cancel discards the draft; dirty close/import/new-case transitions offer Save / Discard / Stay. Export excludes the draft with visible feedback. Panning preserves the draft and map context. Escape location is a point identifier, without editable coordinates.

`workspaceRoutes` exposes the empty workspace route and lazy `/profile` view for the application's lazy map composition. Activation checks the restored case without creating a draft; the view opens it when instantiated. A cancellable deactivation decision protects dirty drafts during browser navigation and is released if navigation is superseded. Replacement cancellation normalizes the URL if the editor was discarded.

Incident moments use native `datetime-local` controls interpreted in the case zone. `incident-time.ts` derives the matching instants with `Intl`, rejects skipped DST times, and exposes repeated-hour choices. An unchanged imported instant keeps its original offset/precision. Date-only values stay native dates and unknown times remain descriptions, without inventing hours.

`CaseControls` consumes the same store and provides new case, import confirmation with case/animal/count summary, cancellation, export and storage recovery. Export captures the current committed snapshot and adds only file metadata; it never changes the document, revision or save acknowledgement. Invalid startup snapshots are retained until explicit replacement. The case contract loads asynchronously for validation/file transfer to keep it outside the initial map bundle.

Map center, zoom and the requested basemap are committed through the same writer without changing factual case timestamps. A map-provider fallback does not erase a stored satellite preference; explicitly choosing OSM does. View restoration does not emit a user edit. Address-search navigation updates the current document's view when a case is active.

`AddressSearch` uses Signal Forms and submits only on Enter or the search button. Its `resultSelected: AddressSearchResult` output contains an ID, label, latitude and longitude. The consumer may move the map (F03) or propose draft coordinates for explicit point confirmation (F07); selection itself never creates a point. Search input/results are transient UI state, outside the future case document.

`AddressSearchClient` calls the same-origin `/api/address-search?q=...`, validates the transport response, and performs no automatic retries. There are no direct browser requests to the geocoder.

Run `npm exec nx run workspace:typecheck`, `npm exec nx run workspace:test` and `npm exec nx run workspace:lint`. Browser acceptance is in `apps/web-e2e/src/address-search.spec.ts`, `apps/web-e2e/src/case-persistence.spec.ts`, `apps/web-e2e/src/animal-profile.spec.ts`, `apps/web-e2e/src/photos.spec.ts` and `apps/web-e2e/src/filters.spec.ts`.

`map-engine` is the Angular-to-Leaflet adapter, with no case store injection or business rules. The screen derives rendering inputs and sends them through template bindings; outputs call store commands. Leaflet lifecycle, layers, restoration feedback suppression and eventual layer reconciliation belong inside the adapter. No separate `MapState` or speculative point/area APIs are introduced by this refactor.

The lazy workspace page projects CaseControls into AppHeader beside the logo, with a separate New Case button directly before Help. Case identity uses the committed animal name or case title. JSON actions use CDK Menu (keyboard navigation, Escape and focus restoration); live save/error/recovery feedback and confirmation dialogs remain owned by CaseControls. The header and map share the route-scoped store; AppHeader itself has no workspace/store dependency. The previous floating case panel is removed.

`PointWorkspace` composes the left floating place list, an independent bottom-right selected-place panel, point form and removal confirmation. Closing details clears the selection; collapsing the list does not hide details. Selecting another place during point editing resolves the current draft before opening the new details. A point session contains its initial and working drafts; only one profile or point session can exist. Map/address placement writes the same Signal Forms draft with a session ID. Leaflet receives computed `mapPlaces` / `mapPointDraft`, emits coordinates/selection, and never injects CaseStore. New points use UUIDs; edits retain IDs, photos and entries. Escape assignment lives only in `case.escape.escapePointId`. Point removal retains unrelated records/assets and unlinks deleted observations, preserving their sighting in the check description while changing its result to `other_or_inconclusive`.

Both profile guards tear down pending decisions when navigation is superseded. Point/profile/import transitions share the same lifecycle, including cancellation of lazy validation. Phone list collapse is initialized from the CDK breakpoint; user toggles remain presentation state. Address-search help stays visible for a nonempty query so focus changes cannot move a result during a mouse click.

F08 adds `withEntryEditing` to the same CaseStore and shared editor lifecycle. Profile, point and history sessions share one ID sequence. `PointHistory` renders computed chronological sections, independent identification/rejection, type-specific forms and removal confirmation inside the selected-place panel. All form writes stay in its session-scoped Signal Forms draft; point selection (including map clicks), profile navigation and file replacement resolve dirty drafts first. Profile/history time conversion shares `EventTimeDraft`, preserving the case zone and imported time precision. Lightweight case-domain/history projections keep synchronous counts/order independent of lazy Zod validation. The map receives plain accent colors and summary text, without identification policy. Confirmed Save/Cancel restores focus and scroll to the place heading.

F14 filter policy lives in the framework-free `filters/case-filter.ts`. Role filters include the derived escape-location role from `case.escape.escapePointId`. Entry-type and period filters require a place to have a matching entry; without them, places without history remain visible. Periods are inclusive local days in the case time zone: exact/approximate instants use their local day, date-only entries their date, and ranges match when their possible days overlap the period (open ends are unbounded). Unknown times match only with the explicit option. Manually rejected reports are hidden by default; hiding them never hides a place or its other matching entries, and different-animal identification is unrelated to rejection. `mapPlaces` keeps stable point numbers and counts only matching observations. The selected place keeps its full history: matching entries are highlighted, while rejected reports have their own show/hide control. `CaseFilters` binds store values directly and dispatches intents; export always serializes the committed document.
